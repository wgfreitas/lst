## Raciocínio (passos 1 a 4)

**Passo 1. Pontos de comunicação**

| # | Fronteira | O que passa por ela |
|---|---|---|
| P1 | ambiente/`.env` → `Settings` | variáveis `LLM_*`, validadas por faixa |
| P2 | CLI → pipeline | caminho do log, chave da API, `--dry-run` |
| P3 | pipeline → cliente HTTP | um `POST /chat/completions` por evento, com `Authorization`, `model`, `max_tokens` e `response_format` |
| P4 | cliente HTTP ↔ servidor | conexão, timeout, status HTTP e novas tentativas |
| P5 | resposta → interpretação | `choices[0].message.content` → JSON com os 3 campos |
| P6 | interpretação → relatório | eventos explicados × "## Eventos não explicados" |
| P7 | pipeline → CLI | exceção → código de saída + mensagem pt-BR no stderr |

**Passos 2 e 3. Falhas possíveis e comportamento esperado**

| Ponto | Falha injetada | Comportamento esperado pelo contrato |
|---|---|---|
| P1 | valor fora da faixa, valor não numérico ou modo desconhecido (por variável e por `.env`) | `ValidationError`; na CLI: código 1, stderr, sem traceback, 0 requisições |
| P2 | chave ausente ou vazia | código 1, mensagem documentada, 0 requisições; `--dry-run` dispensa a chave |
| P2 | arquivo inexistente | código 2, "Erro: arquivo não encontrado: ...", 0 requisições |
| P4/P7 | conexão recusada ou derrubada | código 1, saída controlada (o texto não é documentado) |
| P4/P7 | timeout de leitura | código 1, "Timeout ao consultar o LLM: ..." |
| P4/P7 | 401 no 1º evento ou no meio do lote | código 1, "Erro de autenticação no provedor LLM: ...", sem nova tentativa, a varredura para ali |
| P4 | 429/5xx temporário | nova tentativa; relatório completo |
| P4 | 429/5xx persistente | exatamente 1 + `LLM_MAX_RETRIES` chamadas; exceção propagada |
| P4 | 400 (outro motivo), 401, 403, 404, 422 | 1 chamada, sem nova tentativa e sem degradação; exceção |
| P3/P4 | 400 por `response_format` no modo auto | json_schema → json_object → sem `response_format`; um 400 no último degrau é erro |
| P3/P4 | 400 com o modo fixado | erro, sem degradação |
| P5/P6 | 200 com `content` vazio ou nulo, não-JSON, campo faltando, `severity` inválida, `choices` vazio, corpo vazio ou HTML, JSON truncado | 1 + `LLM_PARSE_RETRIES` chamadas por evento; o evento vai para "## Eventos não explicados"; relatório gerado; CLI com código 0 |
| P5 | cercas markdown, texto em volta do JSON, `severity` em maiúsculas | **não** é erro (controle negativo: nenhuma requisição extra) |

**Passo 4. Casos de borda**
- **Limites das faixas:** cada limite é aceito (1.0/300.0, 0/5, 0/3, 64/4096 e os 4 modos), e o primeiro valor fora dele é rejeitado.
- **Contagem exata de chamadas:** `LLM_MAX_RETRIES` em 0, 2 e 5; `LLM_PARSE_RETRIES` em 0, 1 e 3.
- **Contadores separados:** com `LLM_MAX_RETRIES=5`, o número de novas requisições por conteúdo inválido não pode aumentar.
- **Resposta cortada:** `LLM_MAX_TOKENS=64` com `finish_reason=length`.
- **"Resposta vazia" em três níveis:** `content` vazio, `choices` vazio e corpo vazio.
- **Chave e lote:** chave vazia tratada como ausente; 401 no meio do lote.

**Decisões onde o contrato não diz nada**
- **Tipo da exceção:** o contrato não diz qual exceção `run_pipeline` lança. Os testes verificam só que ela é propagada (e não vira "evento não explicado"), mais a contagem de chamadas.
- **Timeout e falha de conexão:** não se diz se têm nova tentativa, então esses testes fixam `LLM_MAX_RETRIES=0`.
- **Degradação do modo auto:** não se diz se ela vale para os eventos seguintes, então só a sequência do 1º evento é exigida.
- **Formato da seção de não explicados:** não é especificado. Os testes verificam que a seção existe e não está vazia, e contam os "### Próxima ação".
- **Traceback:** o `CliRunner` também devolve código 1 quando há exceção não tratada. Por isso "sem traceback" é verificado exigindo `SystemExit` em `result.exception`.
- **Ambiente de teste:** requer pytest-asyncio com `asyncio_mode = auto` (como no exemplo), respx e Click ≥ 8.2, que separa o stderr no `CliRunner()` padrão. O backoff é zerado para os testes rodarem rápido.

"""Testes de integração dos casos de ERRO entre o LST e o provedor de LLM (API compatível com OpenAI).

O provedor é sempre simulado por respx: nenhum teste acessa a rede. Cada docstring indica a regra
do contrato verificada. Os testes da CLI são síncronos, porque a CLI cria o próprio event loop; os
de ``run_pipeline`` são assíncronos, como no exemplo do projeto.

def make_settings(**overrides: object) -> Settings:
    """Configuração isolada: ignora o .env local e aponta para o servidor simulado."""
    values: dict[str, object] = {
        "llm_api_key": API_KEY,
        "llm_model": "fake-model",
        "llm_base_url": "https://llm.test/v1",
    }
    values.update(overrides)
    return Settings(_env_file=None, **values)


def chat_completion(content: str | None, finish_reason: str = "stop") -> httpx.Response:
    """Resposta 200 no formato chat.completion com o conteúdo dado."""
    return httpx.Response(
        200,
        json={
            "id": "chatcmpl-fake",
            "object": "chat.completion",
            "created": 0,
            "model": "fake-model",
            "choices": [
                {
                    "index": 0,
                    "message": {"role": "assistant", "content": content},
                    "finish_reason": finish_reason,
                }
            ],
        },
    )


def api_error(
    status: int,
    message: str,
    *,
    param: str | None = None,
    code: str | None = None,
    headers: dict[str, str] | None = None,
) -> httpx.Response:
    """Resposta de erro no formato das APIs compatíveis com OpenAI."""
    error = {"message": message, "type": "invalid_request_error", "param": param, "code": code}
    return httpx.Response(status, headers=headers, json={"error": error})


def response_format_rejected() -> httpx.Response:
    """400 causado por `response_format` (modo de saída estruturada não suportado)."""
    return api_error(
        400,
        "Invalid parameter: 'response_format' of this type is not supported with this model.",
        param="response_format",
    )


def bad_request_other_reason() -> httpx.Response:
    """400 por motivo alheio a `response_format`."""
    return api_error(
        400,
        "This model's maximum context length is 8192 tokens.",
        param="messages",
        code="context_length_exceeded",
    )


def mode_of(request: httpx.Request) -> str | None:
    """Tipo de `response_format` enviado na requisição (None quando ausente)."""
    response_format = json.loads(request.content).get("response_format")
    return None if response_format is None else response_format["type"]


def explained(report: str) -> int:
    """Quantidade de eventos explicados no relatório."""
    return report.count("### Próxima ação")


def unexplained_section(report: str) -> str:
    """Conteúdo da seção "## Eventos não explicados" ('' quando ausente)."""
    _, found, rest = report.partition(UNEXPLAINED)
    return rest.strip() if found else ""


def run_cli(*args: str) -> Result:
    """Invoca `lst scan` como descrito no contrato."""
    return CliRunner().invoke(app, ["scan", *args])


def run_cli_counting_requests(*args: str) -> tuple[Result, int]:
    """Roda a CLI contra um provedor simulado que aceita tudo e só conta as requisições."""
    with respx.mock(assert_all_called=False) as router:
        route = router.route().mock(side_effect=lambda request: chat_completion(VALID_REPLY))
        result = run_cli(*args)
    return result, route.call_count


def flat(text: str) -> str:
    """Normaliza espaços para a busca não depender de quebras de linha do console."""
    return " ".join(text.split())


def assert_controlled_exit(result: Result, code: int, message: str = "") -> None:
    """Saída controlada: código esperado, mensagem no stderr, sem traceback e sem relatório."""
    assert result.exit_code == code, result.output
    # O CliRunner devolve código 1 também para exceção não tratada; só SystemExit é saída controlada.
    assert isinstance(result.exception, SystemExit), repr(result.exception)
    assert result.stderr.strip(), "o erro deveria ser explicado no stderr"
    assert message in flat(result.stderr)
    assert "Traceback" not in result.output
    assert REPORT_HEADER not in result.stdout

@pytest.mark.parametrize("status", [429, 500, 502, 503, 504])
async def test_transient_http_failure_is_retried_and_event_recovered(status: int) -> None:
    """Regra: LLM_MAX_RETRIES cobre falhas transitórias (5xx, rate-limit); a nova tentativa bem
    sucedida gera o relatório completo, sem rodapé, com a chave só no cabeçalho Authorization."""
    headers = {"Retry-After": "0"} if status == 429 else None
    replies = [api_error(status, "Falha transitória simulada.", headers=headers)]
    replies += [chat_completion(VALID_REPLY) for _ in range(FLAGGED_EVENTS)]
    with respx.mock(assert_all_called=True) as router:
        route = router.post(ENDPOINT).mock(side_effect=replies)
        report = await run_pipeline(FIXTURE, make_settings(llm_max_retries=1))

    assert route.call_count == FLAGGED_EVENTS + 1
    assert explained(report) == FLAGGED_EVENTS
    assert UNEXPLAINED not in report
    for call in route.calls:
        assert call.request.headers["Authorization"] == f"Bearer {API_KEY}"
        assert API_KEY not in call.request.content.decode()


@pytest.mark.parametrize("max_retries", [0, 2, 5])
@pytest.mark.parametrize("status", [429, 503])
async def test_persistent_transient_failure_stops_after_max_retries(

) -> None:
    """Regra: no máximo LLM_MAX_RETRIES novas tentativas (faixa [0, 5]); esgotadas, run_pipeline

# ------------------------------------------------------------ P3/P4. degradação de response_format


@pytest.mark.parametrize(
    ("accepted", "expected_start"),
    [
        ("json_object", ["json_schema", "json_object"]),
        (None, ["json_schema", "json_object", None]),
    ],
    ids=["aceita-json_object", "aceita-sem-response_format"],
)
async def test_auto_mode_degrades_on_response_format_400(
    accepted: str | None, expected_start: list[str | None]
) -> None:
    """Regra: modo auto — tenta json_schema; 400 por `response_format` → json_object; de novo →
    sem `response_format`. O schema exige os três campos e a chave nunca vai no corpo."""

    def provider(request: httpx.Request) -> httpx.Response:
        if mode_of(request) == accepted:
            return chat_completion(VALID_REPLY)
        return response_format_rejected()

    with respx.mock(assert_all_called=True) as router:
        route = router.post(ENDPOINT).mock(side_effect=provider)
        report = await run_pipeline(FIXTURE, make_settings(llm_structured_mode="auto"))

    modes = [mode_of(call.request) for call in route.calls]
    assert modes[: len(expected_start)] == expected_start
    assert set(modes) <= set(expected_start)  # não degrada além do necessário
    assert explained(report) == FLAGGED_EVENTS
    assert UNEXPLAINED not in report

    json_schema = json.loads(route.calls[0].request.content)["response_format"]["json_schema"]
    assert json_schema["name"] == "triage_explanation"
    assert json_schema["strict"] is True
    assert set(json_schema["schema"]["required"]) == {"explanation", "severity", "next_action"}
    assert all(API_KEY not in call.request.content.decode() for call in route.calls)


async def test_auto_mode_fails_when_last_fallback_is_also_rejected() -> None:
    """Regra: o modo auto tem só três degraus; um 400 na requisição sem `response_format` é erro
    propagado — sem laço de novas tentativas, mesmo com LLM_MAX_RETRIES=5."""

    def provider(request: httpx.Request) -> httpx.Response:
        if mode_of(request) is None:
            return bad_request_other_reason()
        return response_format_rejected()

    with respx.mock(assert_all_called=True) as router:
        route = router.post(ENDPOINT).mock(side_effect=provider)
