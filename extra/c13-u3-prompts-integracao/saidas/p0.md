Segue uma suíte de integração que roda o LST de ponta a ponta (CLI → leitura do log → detecção → cliente HTTP) contra um endpoint `/chat/completions` simulado com respx, sem nenhum acesso à rede.

### Premissas

- **O respx só intercepta o `httpx`.** Isso cobre o LST se ele usa `httpx` diretamente ou o SDK `openai` ≥ 1.0, que roda sobre `httpx`. Se o LST usar `requests`, o respx não enxerga as chamadas; nesse caso o equivalente é `responses` ou `requests-mock`.
- **O CLI roda no mesmo processo do pytest**, chamando `main(argv)`, e não via `subprocess`: o mock só existe na memória do processo de teste.
- **Interface assumida.** Sem o código do LST em mãos, assumi `lst.cli.main(argv) -> int`, configuração por variáveis de ambiente (`LST_API_BASE_URL`, `LST_API_KEY`, `LST_MODEL`, `LST_TIMEOUT`, `LST_MAX_RETRIES`) e explicações impressas no stdout. Tudo o que depende disso fica no bloco `PONTOS DE ADAPTAÇÃO` de `apoio.py`.

### Contrato verificado

| Cenário simulado | Comportamento esperado do LST |
|---|---|
| 200 válido | Uma requisição por evento suspeito, nenhuma para log limpo e nenhuma linha benigna enviada; `POST {base}/chat/completions` com `Authorization: Bearer`, `model` e `messages`; timeout configurado no cliente; `choices[0].message.content` no stdout; exit 0 |
| 401 | Aborta na primeira requisição, sem retentar |
| 429 | Retenta respeitando `Retry-After`; se persistir, desiste após `MAX_RETRIES` e aborta |
| 500, 502 (HTML de proxy), 503 | Retenta com backoff; se persistir, aborta |
| Timeout de conexão ou de leitura | Retenta; se persistir, aborta |
| 200 com corpo inválido | Falha controlada |

Toda falha deve terminar com código ≠ 0 e uma mensagem que explique a causa, sem traceback e sem expor a chave da API. Onde o LST divergir disso de propósito, ajuste o teste; onde divergir por acidente, o teste achou um bug.

```python
"""Dados de exemplo, respostas simuladas e utilitários dos testes de integração.

Somente o bloco PONTOS DE ADAPTAÇÃO depende da interface interna do LST.
"""
from __future__ import annotations

import json
import re
from collections.abc import Callable
from dataclasses import dataclass

import httpx
import respx

# =============================================================================
# PONTOS DE ADAPTAÇÃO
# =============================================================================


def invocar_cli(argv: list[str]) -> int | None:
    """Executa o CLI do LST no mesmo processo do pytest (exigência do respx).

    Com Click/Typer, `return app(argv)` também funciona: o SystemExit que eles
    levantam é tratado pela fixture `executar_lst`.
    """
    from lst.cli import main  # import tardio: o ambiente de teste já está aplicado

    return main(argv)


BASE_URL = "https://llm.test/v1"  # TLD .test (RFC 2606): nunca resolve na internet
API_KEY = "sk-teste-chave-falsa-0123456789"
MODEL = "modelo-de-teste"
TIMEOUT_S = 7
MAX_RETRIES = 2  # => no máximo 1 + 2 = 3 tentativas por evento
LST_LOGGER = "lst"  # logger raiz do pacote (logging.getLogger(__name__))

PREFIXO_ENV = "LST_"
ENV = {
    "LST_API_BASE_URL": BASE_URL,
    "LST_API_KEY": API_KEY,
    "LST_MODEL": MODEL,
    "LST_TIMEOUT": str(TIMEOUT_S),
    "LST_MAX_RETRIES": str(MAX_RETRIES),
}
# Variáveis reais que o LST ou o SDK poderiam ler (credencial ou endpoint de verdade)
VARIAVEIS_A_LIMPAR = ("OPENAI_API_KEY", "OPENAI_BASE_URL", "OPENAI_ORG_ID", "OPENAI_PROJECT_ID")

# Linhas que o detector do LST deve marcar como suspeitas, cada uma isoladamente.
# Chave = marcador único (IP de documentação, RFC 5737) que precisa aparecer no
# prompt enviado à API: é ele que liga cada requisição ao seu evento.
EVENTOS_SUSPEITOS = {
    "203.0.113.10": "Oct 12 03:14:07 srv01 sshd[1201]: Failed password for root from 203.0.113.10 port 51122 ssh2",
    "198.51.100.23": "Oct 12 03:14:09 srv01 sshd[1203]: Failed password for invalid user admin from 198.51.100.23 port 40002 ssh2",
    "192.0.2.77": "Oct 12 03:15:12 srv01 sshd[1207]: Invalid user oracle from 192.0.2.77 port 33210",
}
LINHAS_BENIGNAS = [
    "Oct 12 03:14:00 srv01 systemd[1]: Starting Daily apt upgrade and clean activities...",
    "Oct 12 03:14:30 srv01 kernel: [12345.678901] e1000e: eth0 NIC Link is Up 1000 Mbps Full Duplex",
]
_ev = list(EVENTOS_SUSPEITOS.values())
LOG_AMOSTRA = "\n".join([LINHAS_BENIGNAS[0], _ev[0], _ev[1], LINHAS_BENIGNAS[1], _ev[2]]) + "\n"

# =============================================================================
# Respostas simuladas no formato da API da OpenAI
# =============================================================================


def resposta_ok(conteudo: str) -> httpx.Response:
    return httpx.Response(
        200,
        json={
            "id": "chatcmpl-teste",
            "object": "chat.completion",
            "created": 1760238000,
            "model": MODEL,
            "choices": [
                {
                    "index": 0,
                    "message": {"role": "assistant", "content": conteudo},
                    "finish_reason": "stop",
                }
            ],
            "usage": {"prompt_tokens": 150, "completion_tokens": 40, "total_tokens": 190},
        },
    )


def resposta_erro(
    status: int,
    mensagem: str,
    tipo: str,
    codigo: str | None = None,
    headers: dict[str, str] | None = None,
) -> httpx.Response:
    return httpx.Response(
        status,
        headers=headers,
        json={"error": {"message": mensagem, "type": tipo, "param": None, "code": codigo}},
    )


def roteiro(
    *passos: httpx.Response | type[httpx.TimeoutException],
) -> Callable[[httpx.Request], httpx.Response]:
    """Side effect do respx que segue um roteiro: um passo por requisição, em ordem,
    repetindo o último indefinidamente. Um passo é uma resposta ou uma classe de
    timeout do httpx, levantada com a mensagem real ("timed out") e vinculada à
    requisição, como o transporte de verdade faria."""
    fila = list(passos)

    def _efeito(request: httpx.Request) -> httpx.Response:
        passo = fila.pop(0) if len(fila) > 1 else fila[0]
        if isinstance(passo, type):
            raise passo("timed out", request=request)
        return passo

    return _efeito


# =============================================================================
# Inspeção das requisições capturadas
# =============================================================================


def corpo(request: httpx.Request) -> dict:
    return json.loads(request.content)


def texto_enviado(request: httpx.Request) -> str:
    """Todo o texto das mensagens (content como string ou como lista de partes)."""
    partes: list[str] = []
    for mensagem in corpo(request)["messages"]:
        conteudo = mensagem.get("content")
        if isinstance(conteudo, str):
            partes.append(conteudo)
        elif isinstance(conteudo, list):
            partes += [p.get("text", "") for p in conteudo if isinstance(p, dict)]
    return "\n".join(partes)


def marcador_do_evento(request: httpx.Request) -> str:
    """Identifica o evento da amostra contido na requisição (exige exatamente um)."""
    texto = texto_enviado(request)
    achados = [m for m in EVENTOS_SUSPEITOS if m in texto]
    assert len(achados) == 1, f"esperava 1 evento por requisição, achei {achados}:\n{texto}"
    return achados[0]


def marcadores_enviados(rota: respx.Route) -> list[str]:
    return [marcador_do_evento(chamada.request) for chamada in rota.calls]


# =============================================================================
# Resultado de uma execução do CLI
# =============================================================================


@dataclass
class Execucao:
    codigo: int
    stdout: str
    stderr: str
    logs: str

    @property
    def saida(self) -> str:
        """Tudo o que o operador veria: stdout, stderr e logs do LST."""
        return "\n".join((self.stdout, self.stderr, self.logs))


def assert_falha_controlada(resultado: Execucao, padrao_mensagem: str | None = None) -> None:
    """Código != 0, mensagem que explica a causa, sem traceback e sem expor a chave."""
    saida = resultado.saida
    assert resultado.codigo != 0, f"esperava código de saída != 0:\n{saida}"
    if padrao_mensagem:
        assert re.search(padrao_mensagem, saida, re.IGNORECASE), (
            f"a mensagem não explica a causa (esperava /{padrao_mensagem}/):\n{saida}"
        )
    assert "Traceback (most recent call last)" not in saida, saida
    assert API_KEY not in saida, "a chave da API apareceu na saída"
```

```python
    """Servidor simulado, interceptado no transporte do httpx (a requisição capturada é

    (assert_all_mocked, padrão do respx): nenhum teste alcança a rede de verdade."""
    with respx.mock(base_url=BASE_URL, using="httpx", assert_all_called=False) as router:
        yield router


@pytest.fixture
def rota_chat(api: respx.MockRouter) -> respx.Route:
    return api.post("/chat/completions", name="chat_completions")


@pytest.fixture
def executar_lst(
    capsys: pytest.CaptureFixture[str], caplog: pytest.LogCaptureFixture
) -> Callable[..., Execucao]:
    """Roda o CLI do LST em processo; devolve código de saída, stdout, stderr e logs."""
    caplog.set_level(logging.INFO, logger=LST_LOGGER)

    def _executar(*args: object) -> Execucao:
        erro_extra = ""
        try:
            codigo = invocar_cli([str(a) for a in args])
        except SystemExit as exc:  # argparse, Click/Typer ou sys.exit(...)
            if exc.code is None or isinstance(exc.code, int):
                codigo = exc.code
            else:  # sys.exit("mensagem"): o Python imprime a mensagem e sai com 1
                codigo, erro_extra = 1, f"\n{exc.code}"
        out, err = capsys.readouterr()
        logs = "\n".join(
            caplog.handler.format(registro)
            for registro in caplog.records
            if registro.name == LST_LOGGER or registro.name.startswith(f"{LST_LOGGER}.")
        )
        return Execucao(codigo or 0, out, err + erro_extra, logs)

    return _executar
```

### `tests/integration/test_comunicacao_erros.py`

```python
"""Comunicação LST -> API com respostas de erro: 401, 429, 5xx, timeout e 200 inválido.

Contrato: erros transitórios (429, 5xx, timeout) são retentados até MAX_RETRIES
vezes, com pausa entre as tentativas; esgotadas as tentativas, ou diante de erro
definitivo (401), o LST aborta com código != 0 e mensagem clara, sem traceback e
sem expor a chave.
"""
from __future__ import annotations

import httpx
import pytest
import respx

from .apoio import (
    EVENTOS_SUSPEITOS,
    MAX_RETRIES,
    assert_falha_controlada,
    marcadores_enviados,
    resposta_erro,
    resposta_ok,
    roteiro,
)

pytestmark = pytest.mark.integration

TENTATIVAS_POR_EVENTO = 1 + MAX_RETRIES
N_EVENTOS = len(EVENTOS_SUSPEITOS)
TIMEOUTS = [httpx.ConnectTimeout, httpx.ReadTimeout]


def _ok() -> httpx.Response:
    return resposta_ok("Explicação simulada.")


def _assert_reenviou_sem_perder_eventos(rota: respx.Route) -> None:
    marcadores = marcadores_enviados(rota)
    assert marcadores.count(marcadores[0]) == 2, f"o evento que falhou devia ser reenviado: {marcadores}"
    assert sorted(set(marcadores)) == sorted(EVENTOS_SUSPEITOS), f"evento perdido: {marcadores}"


# --- 401: erro definitivo ------------------------------------------------------


def test_401_aborta_sem_retentar(executar_lst, arquivo_log, rota_chat):
    rota_chat.mock(
        return_value=resposta_erro(
            401, "Incorrect API key provided.", "invalid_request_error", "invalid_api_key"
        )
    )

    resultado = executar_lst(arquivo_log)

    assert rota_chat.call_count == 1  # nem retry nem próximo evento: a chave seguiria inválida
    assert_falha_controlada(
        resultado, r"401|autentica|autoriza|unauthori[sz]ed|api.?key|credencia"
    )


# --- 429: limite de requisições ------------------------------------------------


def test_429_retenta_respeitando_retry_after(executar_lst, arquivo_log, rota_chat, esperas):
    rota_chat.side_effect = roteiro(
        resposta_erro(
            429,
            "Rate limit reached for requests.",
            "requests",
            "rate_limit_exceeded",
            headers={"Retry-After": "3"},
        ),
        _ok(),
    )

    resultado = executar_lst(arquivo_log)

    assert resultado.codigo == 0, resultado.saida
    assert rota_chat.call_count == N_EVENTOS + 1
    _assert_reenviou_sem_perder_eventos(rota_chat)
    assert max(esperas, default=0) >= 3, f"Retry-After ignorado; pausas: {esperas}"


def test_429_persistente_esgota_retentativas_e_aborta(executar_lst, arquivo_log, rota_chat):
    rota_chat.mock(
        return_value=resposta_erro(
            429,
            "Rate limit reached for requests.",
            "requests",
            "rate_limit_exceeded",
            headers={"Retry-After": "1"},
        )
    )

    resultado = executar_lst(arquivo_log)

    # Desiste sem martelar a API com os eventos seguintes. Se o seu LST pula o
    # evento e continua, troque por TENTATIVAS_POR_EVENTO * N_EVENTOS.
    assert rota_chat.call_count == TENTATIVAS_POR_EVENTO
    assert_falha_controlada(resultado, r"429|rate.?limit|limite de|too many")


# --- 5xx: falha no servidor ----------------------------------------------------


def _erro_5xx(status: int) -> httpx.Response:
    if status == 502:  # gateways e proxies costumam responder HTML, não JSON
        return httpx.Response(502, html="<html><body><h1>502 Bad Gateway</h1></body></html>")
    return resposta_erro(
        status, "The server had an error while processing your request.", "server_error"
    )


@pytest.mark.parametrize("status", [500, 502, 503])
def test_5xx_transitorio_e_retentado_com_backoff(
    status, executar_lst, arquivo_log, rota_chat, esperas
):
    rota_chat.side_effect = roteiro(_erro_5xx(status), _ok())

    resultado = executar_lst(arquivo_log)

    assert resultado.codigo == 0, resultado.saida
    assert rota_chat.call_count == N_EVENTOS + 1
    _assert_reenviou_sem_perder_eventos(rota_chat)
    assert esperas, "esperava uma pausa (backoff) antes de retentar"


@pytest.mark.parametrize("status", [500, 502, 503])
def test_5xx_persistente_esgota_retentativas_e_aborta(status, executar_lst, arquivo_log, rota_chat):
    rota_chat.mock(return_value=_erro_5xx(status))

    resultado = executar_lst(arquivo_log)

    assert rota_chat.call_count == TENTATIVAS_POR_EVENTO
    assert_falha_controlada(resultado, rf"{status}|servidor|server|indispon|unavailable|gateway")


# --- timeout -------------------------------------------------------------------


@pytest.mark.parametrize("excecao", TIMEOUTS)
def test_timeout_transitorio_e_retentado(excecao, executar_lst, arquivo_log, rota_chat):
    rota_chat.side_effect = roteiro(excecao, _ok())

    resultado = executar_lst(arquivo_log)

    assert resultado.codigo == 0, resultado.saida
    assert rota_chat.call_count == N_EVENTOS + 1
    _assert_reenviou_sem_perder_eventos(rota_chat)


@pytest.mark.parametrize("excecao", TIMEOUTS)
def test_timeout_persistente_esgota_retentativas_e_aborta(
    excecao, executar_lst, arquivo_log, rota_chat
):
    rota_chat.side_effect = roteiro(excecao)

    resultado = executar_lst(arquivo_log)

    assert rota_chat.call_count == TENTATIVAS_POR_EVENTO
    assert_falha_controlada(resultado, r"time.?out|timed.?out|tempo (limite|esgotado)")


# --- 200 com corpo inválido ----------------------------------------------------


@pytest.mark.parametrize(
    "conteudo",
    [
        pytest.param({"json": {"id": "x", "object": "chat.completion", "choices": []}}, id="choices-vazio"),
        pytest.param({"text": "isto não é JSON"}, id="corpo-nao-json"),
    ],
)
def test_200_invalido_falha_de_forma_controlada(conteudo, executar_lst, arquivo_log, rota_chat):
    rota_chat.mock(return_value=httpx.Response(200, **conteudo))

    resultado = executar_lst(arquivo_log)

    assert_falha_controlada(resultado)  # nada de IndexError/KeyError/JSONDecodeError vazando
```

### Ajustes prováveis

- **Entrada, configuração e rotas.** Edite `invocar_cli` e `ENV`. Se URL e modelo vierem por flags, acrescente-as ao `argv` em `invocar_cli`; a chave continua melhor em variável de ambiente. Se o LST faz outras chamadas, como `GET /models` ao iniciar, declare essas rotas na fixture `api`.
- **Amostra de log.** Cada linha de `EVENTOS_SUSPEITOS` precisa ser detectada sozinha pelas regras do LST, e o IP dela precisa aparecer no prompt enviado. Se o detector agrega eventos (por exemplo, "5 falhas do mesmo IP"), adapte a amostra.
- **Abortar ou continuar.** Os testes de falha persistente assumem processamento sequencial e aborto no primeiro evento que esgota as tentativas. Se o LST marca "explicação indisponível" e segue em frente, use `TENTATIVAS_POR_EVENTO * N_EVENTOS` e revise o código de saída esperado.
- **Código de saída.** Assumi 0 para execução bem-sucedida, com ou sem achados. Se o LST sinaliza achados pelo código de saída, como um linter, ajuste os `codigo == 0`.

- **Configuração lida no import.** Se o LST lê variáveis de ambiente no nível do módulo, um teste que importe `lst` antes congela a configuração real. Mova a leitura para dentro de `main()`.
